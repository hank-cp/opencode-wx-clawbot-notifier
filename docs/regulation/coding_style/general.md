# 通用编码风格

> 本文件是针对未支持语言的通用编码规范。当项目所用语言没有专门的风格指南时，以本文件作为基线。

## 通用格式

- 使用 UTF-8 编码、LF 换行
- 使用项目指定的格式化工具
- 缩进遵循项目约定（推荐 2 或 4 个空格）
- 行长度不应超过 100 个字符
- 文件末尾保留一个空行

## 文件组织

### 命名

- 源文件遵循项目约定（推荐 `kebab-case` 或 `snake_case`）
- 目录名遵循项目约定（推荐 `kebab-case`）
- 测试文件命名遵循项目约定

### 导入 / 依赖解析

1. 标准库 / 内置模块
2. 第三方依赖
3. 项目内部模块

### 文件结构

- 优先每个文件只保留一个主要导出
- 辅助类型/函数使用具名导出
- 每个模块对外暴露清晰的公共 API

## 命名约定

### 变量

- 遵循项目约定（推荐 `camelCase` 或 `snake_case`）
- 作用域短 → 名称短
- 作用域长 → 使用描述性名称
- 布尔变量使用疑问词前缀
- 不使用匈牙利命名法

### 常量

- 遵循项目约定（推荐 `UPPER_SNAKE_CASE`）

### 函数

- 遵循项目约定（推荐 `camelCase` 或 `snake_case`）
- 以动词开头

### 类型 / 接口 / 类

- 遵循项目约定（推荐 `PascalCase`）
- 接口/类型名不加前缀

### 枚举 / 联合类型

- 遵循项目约定

## 类型安全

- 避免动态类型 / any 类型
- 优先使用类型注解 / 类型标注
- 显式处理错误；绝不吞掉异常

## 函数设计

### 参数

- 超过 3 个参数时使用对象/结构体参数

### 返回值

- 优先返回具体类型
- 可空场景使用项目约定（例如 `Result<T, E>`、`Optional<T>`、`(T, error)`）

## 控制流

- 优先使用提前返回，减少嵌套层级

## 异步处理

- 使用语言/框架推荐的异步模式

## 错误处理

- 所有错误必须显式处理
- 在系统边界校验输入
- 不在内部逻辑中添加“不可能发生”的错误处理

## 日志

- 使用项目统一的日志模块
- 日志消息使用英文
- 在关键路径上记录 info/debug 日志

## 注释与文档

- 代码注释使用英文
- 为公共 API 添加文档注释
- 为复杂逻辑添加说明性注释

## 占位代码

```
// TODO(username): needs API integration — expected v1.1
// FIXME(username): potential data race under concurrency — needs locking
// HACK(username): temporary workaround — replace after v1.0
```
